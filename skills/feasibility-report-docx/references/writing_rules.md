# 可研报告行文体例

编制可行性研究报告时的统一体例。**先确认模板自身的体例，模板与之冲突时以模板为准**；模板未规定的按本文件执行。

---

## 一、视角与称谓

1. 全篇采用**建设单位视角**，站在项目建设主体的立场陈述需求与方案，如「公司现有采购业务……」「本项目建设将……」。可研报告由建设单位或其委托的咨询方编制，不使用第三方评价口吻（不写「该单位」「业主方」）。
2. 建设单位统一称 `{建设单位}` 或「公司」。**严禁出现**「贵公司」「贵方」「甲方」「招标人」「采购人」等相对方称谓。
3. 不使用第一人称「我们」「我方」——可研报告不是投标文件，投标文件才用「我方」。若本次产物是投标技术标，改按投标文件体例（通篇「我方」）。
4. 涉及第三方时写明角色，如「系统集成单位」「软件供应商」「评审专家」「供应商」，不只写「合作方」。

## 二、文体

1. 正式书面公文体。不用口语、不用营销语、不用感叹句。
2. **禁用营销化词汇**：赋能、抓手、闭环、生态、颠覆、革命性、业界领先（无依据时）、全面提升（无指标时）、颠覆式创新。
3. **禁止自问自答、禁止排比堆砌超过三项**。三处排比可以，五处就是凑字。
4. 一段一个意思，段落长度 80～200 字。超过 250 字拆段。
5. 并列内容用顿号「、」与连接词融入整句，**不用「·」「•」打点**，也不用「一、二、三」在正文段落内做枚举——层次交给标题层级。

## 三、标题与编号

1. 标题层级严格三级以内：章（一/二/三）→ 节（1.1 / 1.2）→ 小节（1.1.1）。**不出现四级标题**，再往下的内容用加粗引导语 + 段落。
2. 标题不加标点，不加「的」结尾的冗词。
3. 同级标题字数尽量接近，词性一致（都是动宾结构，或都是名词结构，不要混）。
4. 标题与正文之间的空段落、编号格式，**沿用模板**，不手工调整。

## 四、数字与单位

1. 数量用阿拉伯数字；概数、成语中的数字用汉字（「数十个」「三年来」）。
2. 百分数写「80%」，不写「百分之八十」；区间写「80%～90%」。
3. 金额单位全文统一，首次出现注明「人民币」与单位（万元），后文只写数字+单位。
4. 时间写「2026 年 9 月」「2026.9—2027.8」，同一文档内不混用两种格式。
5. 计量单位用国家法定单位：人天、人月、TPS、QPS、ms、TB。
6. 技术指标必须带口径：准确率要写清是「抽取准确率」还是「审核准确率」，覆盖率要写清分母是什么。**无口径的指标等于没有指标。**

## 五、术语

1. 同一概念全文一个叫法。首次出现时写全称并括注简称，后文只用简称。
2. 术语与建设内容清单、需求说明书**逐字一致**，不自造同义词，不做「智能化升级」这类模糊改写。
3. 外文缩写首次出现写中文全称 + 英文缩写，如「光学字符识别（OCR）」。
4. 不使用未定义的缩写。

## 六、图表

1. 每张表都要有表序号与表名（「表 2-1 系统模块清单」），放在表格上方。
2. 每张图都要有图序号与图名，放在图下方。
3. 图表必须在正文中被引用（「详见表 2-1」），不被引用的图表删掉。
4. 表格不留空单元格——确实无内容填「—」，不空着。
5. 表格内容用短句或短语，不用整段文字；单元格内不换行。

## 七、前后一致性（评审最容易扣分的地方）

写完通读一遍，专查这几类不一致：

| 类型 | 常见表现 |
|---|---|
| 名称 | 前文「XX管理平台」，后文「XX业务系统」 |
| 数字 | 背景说「年采购 X 项」，效益算「年采购 Y 项」 |
| 指标 | 目标承诺「提升 80%」，效益只算出「提升 50%」 |
| 模块 | 方案写了 7 个模块，进度表只提到 5 个 |
| 工期 | 进度表跨度 12 个月，正文写「一年内建成」但月份对不上 |
| 称谓 | 前文「公司」，后文冒出「贵单位」 |

## 八、定稿前必查

1. 全文检索模板原项目的**业务关键词、系统名、产品名、单位名**，逐项清零（含封面、页眉、页脚、表格、图注）。
2. 全文检索「XX」「待补充」「TODO」「待定」「{」，占位符必须清零。
3. 目录页码与正文核对（更新域之后）。
4. 页码连续性、页眉一致性。
5. 通读一遍查错别字与标点（中文全角标点，括号统一用全角）。
